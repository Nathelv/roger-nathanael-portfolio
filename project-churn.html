Customer Churn Prediction

A machine learning project predicting customer churn using Random Forest, Decision Tree, and Logistic Regression.

Project TypeAcademic Group Project
CourseMachine Learning
RoleMachine Learning & Data Analysis Team Member
FocusPredictive Modelling

The Problem

E-commerce businesses lose revenue when customers churn. Predicting which customers are likely to leave — and understanding the factors behind it — helps businesses act early to retain them. This project uses the E-Commerce Customer Behavior Dataset from Kaggle (originally 50,000 customers and 25 features, with a 28.9% churn rate).

The Solution

We built and compared several classification models — Logistic Regression, Decision Tree, and Random Forest — to predict churn. The workflow covered thorough preprocessing, handling class imbalance with SMOTE (applied only after the train-test split to avoid data leakage), then training and evaluating each model.

My Contribution

Contributed as a Machine Learning & Data Analysis team member across the modelling and analysis workflow, including data preparation, feature selection, and model evaluation.

Technology

PythonRandom ForestDecision TreeLogistic RegressionSMOTEData Analysis

Process

Data Preparation→ Feature Selection→ SMOTE (train only)→ Modelling→ Evaluation

Preprocessing included missing-value handling, outlier removal, duplicate removal, feature engineering, categorical encoding, standardization, and feature selection. Evaluation used an 80:20 hold-out split with stratified 5-fold cross-validation.

Outcome

Random Forest with SMOTE was the strongest overall approach — Testing Accuracy 90.34%, Precision 85.24%, Recall 80.52%, F1-Score 82.81%, and ROC-AUC 92.27%. Feature analysis highlighted variables such as Customer Service Calls, Lifetime Value, and Cart Abandonment Rate.

Limitation: the high training accuracy for Random Forest and Decision Tree indicated possible overfitting. Future improvements noted in the report include model calibration and more advanced explainability such as SHAP.

What I Learned

  • How careful preprocessing (encoding, scaling, outlier and duplicate handling) shapes model quality.
  • Why SMOTE must be applied only to the training set — keeping the test set in its original distribution to avoid data leakage.
  • How to compare models across multiple metrics (accuracy, precision, recall, F1, ROC-AUC) and read signs of overfitting.
